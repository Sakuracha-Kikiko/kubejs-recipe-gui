# kubejs-recipe-gui 行为规格书

> 版本 v0.1（草案，用于从零实现）
> 目标平台：Minecraft 1.21.1 / NeoForge 21.1.x / KubeJS 2101.x / JEI 19.x
> 许可证：MIT
> 状态：功能规格已定稿，待实现验证

---

## 0. 关于本文档

本文档只约定**做什么**，不规定**怎么组织代码**。实现者可自由选择界面库（原版 `Screen` 手绘、自研布局、或任何第三方 UI 库）、模块划分、类命名与网络方案。

几条约定：

- 文中 `type`、`pattern`、`key`、`result`、`ingredient` 等名称来自 Minecraft / NeoForge / KubeJS / 扩展模组自身的公开配方数据格式，属于接口约定，不是对任何第三方实现的复制。
- 本文档不含任何既有实现的源码、类名、注释或界面文案；所有用户可见文字需实现者自行措辞（中英文各一份）。
- 「功能相似」不构成问题：功能清单、交互流程、创意属于思想范畴；需要回避的是**代码、注释、类结构、文案、美术资源**的逐字逐项搬运。
- 与既有项目相比，本规格有意要求**不同的技术路线**：v1 不引入重量级 UI 框架，界面用原版渲染体系自行绘制与布局，从而在实现层面与任何参考项目彻底分开。

## 1. 定位

给 KubeJS 用户一个**在游戏内可视化编辑配方、并直接落盘成 KubeJS 脚本**的工具。

要解决的问题：KubeJS 的配方 API 灵活但门槛高——玩家得记住每种配方类型的 JSON 结构、材料写法（物品 / 标签 / 替代材料 / 数据组件）、以及 `event.custom` / `event.remove` 的用法。手写容易出错，改一次要重启、看日志、再改。

本模组的解法：把「选工作站 → 摆材料 → 设参数 → 预览代码 → 写入脚本」做成一个界面，让玩家所见即所得，且生成的代码可以直接在存档里生效。

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| 工作站 | 一类配方对应的合成设备，例如工作台、熔炉、压印器 |
| 配方类型 | 工作站下的具体序列化类型，例如有序合成、熔炼、切石 |
| 原料 | 配方输入，可以是精确物品、物品标签、或若干替代材料 |
| 原料规格 | 一条原料的完整描述：种类 + 值 + 可选数据组件 |
| 输出 | 配方产物：物品 + 数量 + 可选数据组件 |
| 配方定义 | 一次编辑的完整结果：工作站、类型、输入、输出、参数、ID |
| 生成条目 | 配方定义序列化出的 KubeJS 语句（新增语句和/或删除语句） |
| 写入模式 | 生成条目的组合方式：仅新增 / 删除后新增 / 仅删除 |
| 删除依据 | 删除语句使用的匹配键：ID / 类型 / 来源模组 / 分组 / 输入 / 输出 |

## 3. 范围

### 3.1 v1 必须交付

1. 一个可放置的工作站方块，右键打开编辑界面。
2. 编辑界面：原版 7 类配方（工作台有序、工作台无序、熔炉、烟熏炉、高炉、营火、切石机、锻造台）的完整编辑能力。
3. 原料支持：精确物品、物品标签、逗号分隔的替代材料；可选数据组件（NBT / components）。
4. 输出支持：物品 + 数量 + 可选数据组件。
5. 代码生成：把配方定义渲染成 KubeJS 语句，支持仅新增、删除后新增、仅删除三种模式。
6. 代码预览：界面内实时预览生成的代码。
7. 写入：把预览代码追加到一个固定的服务端脚本文件，写前校验，写后有结果提示。
8. 权限：只有单人房主或服务器管理员可以写入。
9. JEI 集成：从 JEI 配方页一键把材料、配方 ID、来源信息填入编辑器（JEI 为可选依赖）。
10. 中英双语。

### 3.2 v1 明确不做

- 反向解析：读取已有脚本还原成可视化配方。
- 配方书 / 配方解锁逻辑。
- 多人协同编辑、编辑历史、撤销栈（后两个可放 v2）。
- 运行时热重载（写入后让玩家手动 `/reload` 或由 KubeJS 自身触发）。
- 自定义配方注册类型（只编辑已存在的配方类型）。

### 3.3 可选集成（检测到模组才启用，缺失则整组隐藏）

Extended Crafting、Applied Energistics 2、Mekanism。三者都不作为硬依赖：任一组缺失时，模组仍须正常启动，只是不显示对应分组。

> 注意：v1 的硬依赖只允许 NeoForge + KubeJS（+ 可选 JEI）。不要因为想省事引入重量级 UI 库——那是本次重写的初衷之一。

## 4. 用户模型与权限

| 场景 | 打开界面 | 预览代码 | 写入脚本 |
|---|---|---|---|
| 单人游戏（房主） | ✅ | ✅ | ✅ |
| 单人游戏（局域网客人） | ✅ | ✅ | ❌ |
| 专用服务器（管理员 / OP） | ✅ | ✅ | ✅ |
| 专用服务器（普通玩家） | ✅ | ✅ | ❌ |

- 权限判定必须发生在**服务端**：写入动作由客户端发起请求，服务端复核权限后再执行文件 IO，不能只靠客户端禁用按钮。
- 无权限时按钮置灰并给出悬浮提示；若强行触发请求，服务端拒绝并回一条明确提示。
- 界面打开不限制权限：任何人都可以拿它当"配方面板"来算材料、看代码。

## 5. 入口与方块

### 5.1 方块

- 注册一个独立的方块（建议外观接近工作台一类的木制台面，自行设计贴图）。
- 不可被活塞推动，破坏掉落自身。
- 右键（不使用物品）打开界面；潜行右键不打开，避免与放置方块冲突。
- 方块有对应物品形式，可在创造模式物品栏的一个独立分组里找到：
  - Minecraft 自带分组（例如"功能方块"）里也要有入口，避免玩家找不到；
  - 另建一个本模组专属分组，放方块与其说明性物品（如有）。

### 5.2 获取方式

- 创造模式直接取用；
- 生存模式给一个常规合成配方（低成本，例如木板 + 工作台 + 书）。

## 6. 界面结构

### 6.1 整体

默认逻辑尺寸约 600 × 360 逻辑像素，随 GUI 缩放整体缩放，最小可用尺寸 480 × 270。三栏布局：

```
┌──────────────────────────────────────────────────────────────────────┐
│ [原版] [EC] [AE2] [Mekanism]                    ← 集成分组标签（左对齐）│
├───────────────┬──────────────────────────────────┬───────────────────┤
│ 工作站列表     │            编辑区                 │     属性面板       │
│               │                                  │                   │
│ ▸ 工作台       │  ┌───┬───┬───┐   ┌─────────┐     │ ▸ 配方属性         │
│ ▸ 熔炉         │  │   │   │   │   │  输出   │     │ ▸ 配方 ID / 删除    │
│ ▸ 烟熏炉       │  ├───┼───┼───┤   │  数量   │     │ ▸ 生成与写入        │
│ ▸ 高炉         │  │   │   │   │   └─────────┘     │ ▸ 代码预览          │
│ ▸ 营火         │  ├───┼───┼───┤                   │ ▸ JEI 来源          │
│ ▸ 切石机       │  │   │   │   │   [原料设置]      │                   │
│ ▸ 锻造台       │  └───┴───┴───┘                   │                   │
│               │                                  │                   │
│ 配方类型 ▾     │                                  │                   │
├───────────────┴──────────────────────────────────┴───────────────────┤
│ 状态栏：提示 / 错误 / 成功信息                                          │
└──────────────────────────────────────────────────────────────────────┘
```

- 三栏宽度比例约 18% / 50% / 32%，中栏随窗口尺寸伸缩。
- 背景使用原版容器底色 + 边框，保证与游戏风格一致；不要照搬任何现有模组的贴图。
- 状态栏常驻，显示最近一次操作的反馈（成功 / 失败 / 校验错误），文字颜色区分等级。

### 6.2 左栏

**顶部**：集成分组标签，每个已安装模组一个；未安装的模组整组不显示（JEI 不是分组，JEI 是功能）。

**中部**：当前分组下的工作站列表，纵向可滚动，每项显示图标 + 名称；当前选中项高亮。

**底部**：配方类型下拉框，列出当前工作站支持的类型；切换工作站时按该工作站支持的第一个类型重置。

工作台类工作站额外显示一个「有序 / 无序」切换按钮（仅工作台类需要，锻造台等不需要）。

### 6.3 中栏（编辑区）

按工作站类型渲染不同的编辑形态：

| 工作站形态 | 编辑区 |
|---|---|
| 网格类（3×3 / 5×5 / 7×7 / 9×9） | 方格槽位，行列由工作站定义 |
| 单槽类（熔炉、营火、切石机、充能器等） | 一个大槽位 + 一个燃料/预览槽（可选，不参与生成） |
| 多槽类（锻造台、压印器、组合合成） | 按语义命名的若干槽位（如模板 / 基础 / 追加、上 / 中 / 下） |
| 无输入槽类（熵变、化学类） | 输入/输出表单，用下拉选资源类型（物品 / 方块 / 流体 / 气体） |
| 合成台外壳 | 右侧固定一个 3×3 输出预览区（仅视觉，不参与生成） |

**输出区**：固定在中栏右侧，包含输出槽、数量输入框、可选的副产物槽。

**槽位交互**：

- 左键放置/取出光标上的物品。
- 右键从槽位取一个物品（或放一个）。
- Shift + 左键清空槽位。
- 悬停显示物品名称和数量。
- 槽位内物品**不消耗**、不受玩家背包影响，纯数据。

**原料设置面板**：点击任意输入槽位的"设置"角标（或双击槽位）打开一个浮层，用于编辑该槽的原料规格（见 7.5）。浮层关闭后槽位图标同步为最终规格（标签显示为标签书样式，替代材料显示为第一项的图标并带角标）。

### 6.4 右栏（属性面板）

右栏是一个多标签面板，标签顺序固定：

1. **配方属性**：当前配方类型下的全部参数（经验、时间、能量、模式、等级等，按类型动态生成）。
2. **配方 ID 与删除条件**：新增配方的 ID 输入框；删除依据的类型下拉 + 值输入；删除依据的说明文字。
3. **生成与写入**：写入模式三选一（仅新增 / 删除后新增 / 仅删除）；「预览」按钮；「写入」按钮；写入目标路径的静态说明。
4. **代码预览**：只读代码框，显示上一次预览/写入的代码，等宽字体、带行号、可滚动、可全选复制；语法着色可选（不做也能验收）。
5. **JEI 来源**：上一次从 JEI 填入的配方信息（ID、类型、来源模组、分组），只读。

标签页切换时保留各页状态（切换不丢输入）。

### 6.5 浮层与提示

- 原料设置浮层：模态，带遮罩；Esc 或点击遮罩关闭；关闭即保存当前编辑结果（不需要额外"确定"）。
- 确认类浮层（例如"覆盖同名配方？"）：默认焦点在"取消"。
- 错误提示：状态栏文字 +（可选）界面顶部短暂横幅；不弹独立窗口打断操作。

## 7. 交互规格

### 7.1 工作站切换

- 点击左栏项立即切换，中栏与右栏参数区重建；已填的原料与输出在**同一工作站内**切换配方类型时尽量保留（有序 ↔ 无序、熔炉 ↔ 烟熏炉等可保留槽位与输出）。
- 跨工作站切换（例如工作台 → 熔炉）时清空与工作站尺寸/语义不兼容的部分，并在状态栏提示"已重置材料"。

### 7.2 配方类型切换

- 只列出当前工作站真实支持的序列化类型；类型列表来源于运行时的配方注册表或内置常量表，不允许硬编码一份可能过期的字符串表而不做校验。
- 切换后参数区重建；不兼容的参数恢复默认值。

### 7.3 有序 / 无序

- 仅工作台类工作站显示该开关，默认有序。
- 有序：生成时使用网格布局；行/列的空边在生成时裁掉（不是编辑时裁），保证 `pattern` 紧凑。
- 无序：忽略位置，按从左到右、从上到下的顺序收集非空原料。
- 从有位置切换为无序时，把网格中的原料按序收进列表，界面上把网格替换为等量槽位（可滚动）。

### 7.4 输入槽

- 槽位数量与尺寸由工作站定义，例如 3×3 = 9、5×5 = 25、组合合成 = 1 中心 + 8 基座。
- 槽位内容只能来自玩家手持物品或原料设置浮层中的"精确物品"模式。
- 空格子在生成时被跳过；有序配方中空格子会在裁剪后表现为 `pattern` 里的空格。

### 7.5 单槽原料设置

浮层包含：

1. **原料类型**（三选一，单选按钮或分段控件）：
   - 精确物品：值形如 `minecraft:oak_planks`（可省略命名空间，默认 `minecraft`）。
   - 物品标签：值形如 `#minecraft:planks`；输入框允许多选时以逗号分隔多个标签。
   - 替代材料：逗号分隔的多个"精确物品或标签"，表示"任意其一即可"。
2. **值输入框**：等宽字体、带占位提示；失焦时规范化（去空格、补命名空间、标签补 `#`）。
3. **数据组件**：一个开关「写入数据组件」+ 一个多行输入框 + 一个「从槽位读取」按钮（把槽内物品的组件序列化填入输入框）。开关关闭时，生成的原料**不带**组件，且删除匹配也不带组件。
4. **可用标签提示**：根据当前值对应的物品，列出它所属的物品标签及其数量，点击任意标签可直接把原料类型切到"物品标签"并填入该标签。没有可用标签时显示"当前物品没有可用标签"。
5. **校验**：值合法、标签存在（客户端可只做格式校验，服务端写前再校验一次）、替代材料至少 1 项且无重复。

浮层打开时若槽位为空，默认进入"精确物品"模式并聚焦值输入框。

### 7.6 输出

- 输出槽 + 数量框（默认 1，范围 1–99，只接受数字）。
- **数量框的行为约束（硬性）**：
  - 点击数量框不得触发输出槽的放置/清空逻辑——这是最容易出的 bug：把数量框当作槽位的子控件时，事件会冒泡到槽位，导致"点一下数量框物品就没了"。
  - 手动输入的数量**优先于**光标上物品堆叠数：手上拿着一摞 32 个放进输出槽，如果玩家已手动输入 5，则输出数量为 5。
  - 数量框与槽位显示必须同步：改数字后槽位上立刻显示新数量；重新放入同一物品（ID 相同）时数量不得回退为 1。
  - 清空槽位时数量框重置为 1，手动输入状态清除。
  - 数量框为空或非法输入时按 1 处理，不报错。
- 输出物品为空时预览/写入按钮禁用并提示"请先设置输出"。
- 副产物槽（Mekanism 等）：数量 + 概率（0–100%）；概率为空按 0.0 处理。

### 7.7 参数区

按配方类型动态生成，控件类型只有三种：数字输入、开关、下拉。常见参数：

- 烹饪类：经验（浮点，0–1）、时间（整数 tick）。
- 切石类：无需参数。
- 扩展工作台：等级（3×3 / 5×5 / 7×7 / 9×9 由工作站决定，无需另设）。
- 扩展合成类：能量消耗、功率、合成时间、材料数量。
- AE2 压印器：模式（压印 / 刻印）。
- AE2 转化：转化条件（爆炸 / 流体标签 + 标签值）。
- AE2 熵变：模式（加热 / 冷却）；输入输出资源类型（物品 / 方块 / 流体）。
- Mekanism：能量倍数、总能耗、每 tick 能耗、持续时间、副产物概率。

所有数字参数都要做范围校验，越界时标红并在状态栏提示，且阻止写入。

### 7.8 配方 ID

- 输入框可留空；留空时按「自动 ID」规则生成（见 9.7）。
- 手动输入时做格式校验：`namespace:path`，只允许 `[a-z0-9_.-/]`。
- 提供"根据内容重新生成"的小按钮，仅清空输入框并触发下一次生成时重算，不做即时重算。
- 从 JEI 填入时，若 JEI 配方有 ID，自动填入；之后玩家手动改过则以手动值为准（用"是否被手动编辑过"标记，避免 JEI 覆盖用户输入）。

### 7.9 删除依据与写入模式

**删除依据六选一**：

| 依据 | 取值来源 | 生成的删除条件 |
|---|---|---|
| 配方 ID | 配方 ID 输入框 | 按 ID 精确匹配 |
| 配方类型 | 当前配方类型 | 按类型匹配 |
| 来源模组 | JEI 填入或手动输入 | 按命名空间匹配 |
| 配方分组 | JEI 填入或手动输入 | 按分组字符串匹配 |
| 输入材料 | 当前槽位中的原料（可多选） | 按输入匹配 |
| 输出物品 | 当前输出（可多选） | 按输出匹配 |

**写入模式三选一**：

- 仅新增：只生成新增语句。
- 删除后新增：先删除语句，后新增语句，**同一条命令内按此顺序**。
- 仅删除：只生成删除语句；此时输出为空也允许生成。

**规则**：

- 删除依据的值为空时，预览/写入被阻止，提示"当前删除依据没有可用值"。
- 删除条件的匹配是否包含数据组件，跟随 7.5 与 7.6 的"写入数据组件"开关：开关开则条件里带组件，关则不带。

### 7.10 预览与写入

- **预览**：根据当前状态生成代码，填入"代码预览"标签页并自动切过去；同时在状态栏显示"已生成 N 行"。
- **写入**：若预览框为空，先自动执行一次预览；然后请求服务端写入。
- 写入成功：状态栏提示目标路径，并把文件当前内容回显到预览框（让玩家看到落盘结果）。
- 写入失败：状态栏显示原因（无权限 / 文件不可写 / 代码校验失败 / 超过大小上限）。
- 写入完成后不自动 reload；提示玩家"输入 /reload 生效"（KubeJS 自身可能已监听，两条提示都写清楚）。

### 7.11 JEI 填充

- 进入 JEI 任意配方页，点击转移按钮（JEI 自带的"+"）→ 若光标焦点在编辑器界面内，则把该配方填入编辑器。
- 填入内容：输入材料（按槽位顺序尽量匹配到同形状的槽位）、输出与数量、配方 ID、配方类型、来源模组、分组。
- 填入后：`配方 ID 与删除条件` 页的 ID 变为可用，JEI 来源页显示来源信息，状态栏提示"已填入"。
- 不支持的类型（JEI 有但本模组未实现）→ 提示"此配方类型暂不支持编辑"，不做任何修改。
- JEI 未安装时，界面上的 JEI 相关元素全部不显示（不是置灰）。

### 7.12 键盘与焦点

- Esc：有浮层先关浮层，否则关界面。
- Tab / Shift+Tab：在可聚焦控件间移动焦点；焦点框清晰可见。
- Enter：在数量框/ID 框中确认并移出焦点。
- 滚轮：列表与代码框滚动；不在网格上误触改变数量。
- 代码框支持 Ctrl+A / Ctrl+C 复制。

## 9. 代码生成

### 9.1 脚本骨架

生成结果是一个 KubeJS 服务端脚本片段，语义为：

```
ServerEvents.recipes(event => {
  // 删除语句（按写入模式决定是否存在）
  // 新增语句（按写入模式决定是否存在）
})
```

新增语句的语义：**以 JSON 形式声明配方**，通过 KubeJS 的事件 API 注册，并显式指定配方 ID。结构上等价于"`type` 字段 + 各配方字段 + 结果字段 + 指定 ID"。

> 实现时请以 KubeJS 2101 的官方 API 为准确定具体写法（`event.custom` 一族）。不要从任何现有模组的代码里抄模板字符串——这段格式本身是公开 API 约定，但字面写法应由实现者按文档自行组织。

### 9.2 有序配方

- 对网格做边界裁剪：去掉上下左右的空行空列，得到子网格。
- 为子网格中出现的**每种不同原料**分配一个字符：`A`–`Z`、`a`–`z`、`0`–`9`，不够再用 ASCII 符号；分配顺序为从左到右、从上到下的首次出现顺序。
- 输出：`pattern` 为裁剪后的每行字符串（空格表示空位），`key` 为字符到原料表达式的映射。
- 不同原料超过可用字符数时（实际不可能超过 81 种），报错"材料种类过多"。

### 9.3 无序配方

- 收集全部非空原料，输出为原料表达式数组，顺序为从左到右、从上到下。

### 9.4 原料表达式

| 种类 | 表达式 |
|---|---|
| 精确物品，无组件 | `"minecraft:item"` |
| 精确物品，有组件 | 带 `item` 与 `components` 字段的对象，组件内容原样嵌入 |
| 物品标签 | `"#minecraft:planks"`（带组件时为对象形式） |
| 替代材料 | 上述表达式组成的数组 |

### 9.5 输出表达式

- 语义：`Item.of("minecraft:item", 数量)`；带组件时把组件作为第二参数的附加信息（按 KubeJS 2101 的 `Item.of` 签名决定）。
- 数量为 1 时可省略第二个参数。

### 9.6 删除表达式

- 语义：`event.remove({ <键>: <值> })`，键取自 7.9 的六种依据（`id` / `type` / `mod` / `group` / `input` / `output`）。
- 带组件匹配时，值与 9.4 的表达式一致。
- 多条删除依据（输入/输出可多选）时，生成数组或多条语句，语义为"任一匹配即删除"还是"全部匹配才删除"必须明确并在界面上说明——**建议按 KubeJS 的语义选择，界面上明确写出当前语义**。

### 9.7 自动 ID

- 规则：`<模组命名空间>:<工作站短名>_<内容哈希前 8 位>`，例如 `mymod:crafting_3f2a91cd`。
- 哈希输入：有序/无序标志 + 输入表达式 + 输出表达式 + 关键参数，保证同样内容总能得到同样 ID（幂等，重复写入不会制造重复配方）。
- 手动填了 ID 则优先使用手动值。

### 9.8 生成前校验

生成必须拒绝以下情况并给出具体原因：

1. 输入为空（删除模式为"仅删除"时豁免）。
2. 输出为空（同上豁免）。
3. 原料值非法或标签不存在。
4. 数量越界、参数越界。
5. 删除依据为空。
6. 生成结果超过长度上限（单次 64 KB）。

校验失败时不修改预览框与文件，状态栏显示第一条错误。

## 10. 文件写入

- 目标文件：`kubejs/server_scripts/generated_recipes.js`（相对游戏目录的 KubeJS 服务端脚本目录）。
- 文件不存在：创建，并写入文件头（说明本文件由模组生成 + `ServerEvents.recipes` 监听器 + 空事件体）。
- 文件已存在且含本模组生成的事件块：**只向该事件块内追加语句**，不重复创建监听器（多监听器会导致同一条配方被多次注册）。
- 文件已存在但不是本模组生成的内容：在文件末尾追加一个新的事件块，并在状态栏提示"已追加到文件末尾"。
- 幂等：同一配方 ID 已存在时——
  - 内容完全相同：跳过，提示"该配方已存在"；
  - 内容不同：替换该条语句（先删后加），提示"已更新"。
- 大小上限：单次写入 ≤ 64 KB；文件总大小超过 1 MB 时拒绝并提示。
- 写入采用"先写临时文件再原子替换"，避免写一半损坏脚本。
- 所有路径操作限制在 KubeJS 服务端脚本目录内，不允许 `..` 越界。

## 15. 非功能需求

- **性能**：9×9 网格 + 81 个槽位在 1080p/60fps 下流畅；预览生成耗时 < 16 ms（在客户端主线程完成，不做异步）。
- **内存**：不为每个槽位创建独立纹理，复用原版渲染。
- **可测试性**：代码生成器必须是纯函数（配方定义 → 字符串），可用单元测试覆盖每种配方类型与每种写入模式。
- **本地化**：`zh_cn` 与 `en_us` 键完整对齐；不硬编码界面文字。
- **可访问性**：焦点可达、对比度足够、状态栏文本可读。
- **日志**：写入、校验失败、异常均记 INFO/WARN，不含玩家隐私路径（只记相对路径）。

## 16. 验收标准

1. 新建世界装好 KubeJS，放下方块，右键能打开界面，不崩。
2. 摆一个 3×3 有序配方，预览生成的 `pattern` 已裁剪（例如只占 1 行 1 列时 pattern 只有一行一个字符）。
3. 写入后 `kubejs/server_scripts/generated_recipes.js` 出现对应语句，`/reload` 后配方在 JEI/配方书中生效。
4. 再写一次相同配方：文件不重复增长，提示已存在。
5. 输出数量：先放物品再改数量，物品不消失、数量正确；先改数量再放物品，数量保持手输值。
6. 标签原料：写 `#minecraft:planks`，生成的代码里是标签形式，游戏内任意木板都能满足。
7. 替代材料：`minecraft:oak_planks,minecraft:spruce_planks` 生成数组，两种木板都能用。
8. 删除模式：选"仅删除 + 按输出"，写入后原配方消失。
9. 权限：局域网客人点写入，按钮置灰；伪造请求时服务端拒绝。
10. JEI：从 JEI 工作台配方页转移，材料与 ID 被填入，能直接预览。
11. 未安装 EC/AE2/Mekanism 时，只显示原版分组，无报错。
12. 中英文切换后界面无英文残留（或反之）。
